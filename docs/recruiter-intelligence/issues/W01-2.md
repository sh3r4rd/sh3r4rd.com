## Context

Emails preserved in week 0 sit in `archive/raw/` as raw `.eml`. This re-runs the existing `parser` package over them to produce `archive/clean/` records, deterministically and with no LLM calls. Specification: PLAN.md § Week 1.

## Tasks

- [ ] `cmd/backfill` in `lambda-src/email-parser`: list `archive/raw/`, parse each with `internal/parser`, write `archive/clean/{id}.json` in the W01-1 format, SSE-KMS with the W01-1 key
- [ ] Skip mail that SES rejected (SPF, DKIM or spam FAIL), using the verdict headers SES writes into the stored message (`X-SES-Spam-Verdict`, `X-SES-Virus-Verdict`, and the SPF/DKIM results). Check the exact header names on one real archived message first. Apply the same rule as `validateVerdicts`, so the Lambda and the backfill agree
- [ ] Skip existing outputs unless `--force`; print counts (parsed, skipped, rejected, failed) and never email content
- [ ] `--reconcile`: first copy any `incoming/` key missing from `archive/raw/` (tag-free, SSE-KMS, skipping virus-flagged mail), then backfill as usual. This is the catch-up path for invocations whose retries ran out (async retries stop after two, and there is no DLQ) and for failed `archive/clean` writes. Run it after any `email-parser-errors` alarm and before each weekly `JOURNAL.md` entry, well inside the 30-day expiry
- [ ] Tests over the `testdata/` fixtures

## Acceptance criteria

- [ ] One run over the whole archive; a second run writes nothing
- [ ] Recovery test (mocked S3, never the live bucket): with one `archive/clean` record and one `archive/raw` copy missing while the original is still in `incoming/`, `--reconcile` restores both
- [ ] `archive/clean` count = `archive/raw` count − rejected − parse failures, with failures listed by key only
- [ ] `--reconcile` never copies a virus-flagged message
