## Context

`modules/s3/main.tf:15-30` expires every object under `incoming/` after `s3_lifecycle_expiration_days` (default 30). Versioning is off, and the raw `.eml` is the only durable copy of each email body, so every day this waits, the oldest day of corpus is gone for good. Specification: PLAN.md § Week 0.

## Tasks

- [ ] `aws login`, then copy `incoming/` to `archive/raw/` **without tags**: `aws s3 sync "s3://$BUCKET/incoming/" "s3://$BUCKET/archive/raw/" --copy-props metadata-directive` (the default would copy the `sender` tag, which holds the recruiter's email address)
- [ ] Spot-check one copy with `aws s3api get-object-tagging`; it should return no tags
- [ ] `make tf-vars-pull`, set `s3_lifecycle_expiration_days = 3650`, run `terraform -chdir=infra/recruiter-dashboard plan` (only the lifecycle rule changes), `apply`, `make tf-vars-push`
- [ ] Record the inventory in `JOURNAL.md` § Week 0: `archive/raw` object count, and the DynamoDB `COUNT` **minus one** (the `STATS#cache` item)
